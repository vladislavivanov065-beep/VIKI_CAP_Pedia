# Corporate Wiki

## Docker

```bash
cp .env.example .env
# указать ADMIN_USERNAME и ADMIN_TEMP_PASSWORD в .env
docker compose up --build
```

При старте контейнер автоматически применяет миграции, собирает
статику и создаёт первого администратора с логином/паролем из
`ADMIN_USERNAME`/`ADMIN_TEMP_PASSWORD` — если суперпользователь уже
есть, этот шаг пропускается (безопасно при перезапуске контейнера).

Приложение — `http://localhost:8000`.

```bash
docker compose exec web pytest
```

### Публикация через ngrok / другой туннель

Без этого Django ответит `400 Bad Request` на все запросы, включая
главную страницу — узнать домен, выданный ngrok, и указать его в `.env`
**до** запуска `docker compose up`:

```bash
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,.ngrok-free.app
DJANGO_CSRF_TRUSTED_ORIGINS=https://*.ngrok-free.app
```

(`.ngrok-free.app` — маска поддомена, переживает смену адреса при
каждом перезапуске ngrok; если ngrok выдал домен на другом суффиксе,
подставьте его). После изменения `.env` перезапустите контейнер:

```bash
docker compose up -d --build
```

## ИИ-ассистент ("Задай свой вопрос")

Галочка «Спросить у ChatGPT» у вопроса решает, какой из двух режимов
отвечает:

- **Отмечена** — уходит в OpenAI. Требует `OPENAI_API_KEY` в `.env`,
  подчиняется общему переключателю администратора в сайдбаре. Запрос
  уходит только в момент, когда пользователь реально задал вопрос —
  текст статьи никуда не отправляется при её создании или сохранении.
- **Не отмечена (по умолчанию)** — отвечает локальный ИИ, без OpenAI и
  без интернета на момент ответа. Если администратор ещё не обучил
  локальный ИИ (или обучение не удалось), используется простой поиск
  релевантных предложений по тексту текущей статьи.

### Локальный ИИ

Страница «Локальный ИИ» в сайдбаре (только для администраторов, также
`/assistant/local-ai/`) содержит кнопку «Переобучить»: она пересчитывает
эмбеддинги по всем неархивным статьям и сохраняет их в SQLite.

Текст статьи сначала делится на строки (абзацы, заголовки, элементы
списков и ячейки таблиц), а затем соседние строки склеиваются в один
фрагмент, если строка перед ними похожа на незаконченную мысль — не
оканчивается точкой/!/?/: (например, «биллинг адрес» перед строками
«улица такая-то» / «город такой-то» / «индекс такой-то» — типичный адрес
без знаков препинания в каждой строке) — или если их эмбеддинги
семантически близки друг к другу, даже когда обе строки формально
заканчиваются точкой (`apps.assistant.chunking`). Абзац, вводящий список
или таблицу («Случаи, при которых возможен овердрафт.» перед списком этих
случаев), из-за этого попадает в индекс вместе со своим списком/таблицей
как одна цитата, а не по отдельности. После этого ответы на вопросы (при
снятой галочке «Спросить у ChatGPT») находят несколько таких фрагментов
по всем статьям, максимально похожих по смыслу на вопрос, и из них
выбирают точнее всего совпадающий по ключевым словам — с учётом словоформ
и для русского (через pymorphy3-лемматизацию: «рекламу»/«рекламы» —
одно слово), и для английского (через Porter-стемминг: «billing»/
«billed» — тоже одно слово) — а если ни один не совпал по словам, берут
просто самый похожий по смыслу. Возвращается точная цитата, не пересказ.
Генеративная модель здесь не используется: маленькие локальные модели
либо копировали фрагмент целиком, либо иногда отвечали не по теме —
точный отрывок
надёжнее того и другого.

Обучение — это пересчёт индекса, а не тренировка модели с нуля: сама
модель эмбеддингов предобученная и скачивается с Hugging Face **один
раз**, при первом обучении, и кэшируется на диске. Для этого серверу,
на котором развёрнуто приложение, нужен исходящий HTTPS-доступ к
`huggingface.co`. Модель и её кэш задаются в `.env`:

После первого обучения индекс дальше поддерживается автоматически:
сохранение, переименование, архивирование/восстановление статьи или
откат к старой версии пересчитывают эмбеддинги только этой статьи в
фоновом потоке (`apps.assistant.signals` → `apps.assistant.training.
sync_article_embeddings`), без блокировки запроса и без нажатия
«Переобучить» — эта кнопка остаётся нужна только для первого запуска и
для полной пересборки (например, после смены `LOCAL_AI_EMBEDDING_MODEL`,
когда старые векторы уже не в одном пространстве с новыми). Пока
администратор не запустил обучение ни разу, сохранение статей не трогает
ML-модель вообще — не тянет веса и не грузит их в память впустую для тех,
кто этой функцией не пользуется.

```
LOCAL_AI_EMBEDDING_MODEL=intfloat/multilingual-e5-small
LOCAL_AI_MODEL_CACHE_DIR=
```

По умолчанию — небольшая модель (~470 МБ), рассчитанная на работу на CPU
без GPU. Если веса скачать не удалось (нет сети, модель недоступна) — на
странице «Локальный ИИ» появится текст ошибки, а обучение не отметится
как выполненное; ответы на вопросы при этом продолжают работать через
обычный поиск по тексту статьи.
