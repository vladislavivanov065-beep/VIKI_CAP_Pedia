# Corporate Wiki

## Docker

```bash
cp .env.example .env
# указать ADMIN_USERNAME и ADMIN_TEMP_PASSWORD в .env
docker compose up --build
```

При старте контейнер автоматически применяет миграции, собирает
статику и создаёт первого администратора с логином/паролем из
`ADMIN_USERNAME`/`ADMIN_TEMP_PASSWORD` — если суперпользователь уже
есть, этот шаг пропускается (безопасно при перезапуске контейнера).

Приложение — `http://localhost:8000`.

```bash
docker compose exec web pytest
```

### Публикация через ngrok / другой туннель

Без этого Django ответит `400 Bad Request` на все запросы, включая
главную страницу — узнать домен, выданный ngrok, и указать его в `.env`
**до** запуска `docker compose up`:

```bash
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,.ngrok-free.app
DJANGO_CSRF_TRUSTED_ORIGINS=https://*.ngrok-free.app
```

(`.ngrok-free.app` — маска поддомена, переживает смену адреса при
каждом перезапуске ngrok; если ngrok выдал домен на другом суффиксе,
подставьте его). После изменения `.env` перезапустите контейнер:

```bash
docker compose up -d --build
```

## ИИ-ассистент ("Задай свой вопрос")

Галочка «Спросить у ChatGPT» у вопроса решает, какой из двух режимов
отвечает:

- **Отмечена** — уходит в OpenAI. Требует `OPENAI_API_KEY` в `.env`,
  подчиняется общему переключателю администратора в сайдбаре. Запрос
  уходит только в момент, когда пользователь реально задал вопрос —
  текст статьи никуда не отправляется при её создании или сохранении.
- **Не отмечена (по умолчанию)** — отвечает локальный ИИ, без OpenAI и
  без интернета на момент ответа. Если администратор ещё не обучил
  локальный ИИ (или обучение не удалось), используется простой поиск
  релевантных предложений по тексту текущей статьи.

### Анонимизация перед отправкой в OpenAI

Везде, где текст статьи уходит в OpenAI — и здесь, в «Спросить у
ChatGPT», и при обучении локального ИИ, если OpenAI используется для
разбивки статьи на фрагменты (см. ниже) — он сначала анонимизируется
(`apps.assistant.redaction`). Числа (BIN-ы карт, тарифы, лимиты, коды),
ссылки, адреса (строки после «Адрес:»/«Address:»/«Индекс:») и названия
стран заменяются на `[XXX1]`, `[XXX2]` и т.д. Модель видит только
структуру текста и плейсхолдеры, реальные значения ей не передаются.

Реальные значения возвращаются на место после ответа:

- В «Спросить у ChatGPT» модель отвечает, используя плейсхолдеры
  буквально (это прописано в промпте), а перед показом пользователю
  каждый `[XXXn]` заменяется обратно на настоящее значение.
- При разбивке на фрагменты (ниже) ChatGPT вообще не видит и не
  возвращает сам текст — только номера строк, которые нужно
  сгруппировать. Итоговые фрагменты собираются из оригинальных,
  неанонимизированных строк по этим номерам.

Обычные названия мерчантов/брендов («Apple Pay», «Uber», «Amazon» и
т.п.) **не скрываются** — это публичная информация, а не тайна, и статья
о том, какие сервисы поддерживаются, потеряет смысл, если все названия
превратятся в `[XXXn]`. Если у вас есть конфиденциальные названия,
которые автоматика не распознаёт (например, название вашего карточного
партнёра — его от обычного мерчанта не отличить без списка), добавьте их
через запятую в `LOCAL_AI_REDACTED_TERMS`.

Это сопоставление по шаблонам и словарю, а не полноценная NER-модель —
оно ловит те формы данных, которые реально встречаются в статьях (числа,
ссылки, адреса за явной подписью, страны), но не гарантирует, что
никакой чувствительный текст не проскочит в неожиданном формате. Не
полагайтесь на него как на единственную защиту для данных, утечка
которых недопустима.

### Локальный ИИ

Страница «Локальный ИИ» в сайдбаре (только для администраторов, также
`/assistant/local-ai/`) содержит кнопку «Переобучить»: она пересчитывает
эмбеддинги по всем неархивным статьям и сохраняет их в SQLite.

Текст статьи сначала делится на строки (абзацы, заголовки, элементы
списков и ячейки таблиц), а затем решается, какие строки объединить в
один фрагмент. Если задан `OPENAI_API_KEY` и ИИ-ассистент включён — это
решает ChatGPT (`apps.assistant.chunking_remote`): он получает только
пронумерованные строки с анонимизированными данными (см. выше) и
возвращает номера строк, на которых начинается каждый следующий
фрагмент — не сам текст и не полную разбивку всех строк по группам:
для длинной статьи (сотни строк) попросить модель ровно один раз
безошибочно разложить каждую строку по группам ненадёжно, а пропуск
хотя бы одной точки начала фрагмента — не проблема, просто немного
сдвигает границу. Ни один фрагмент не может получиться длиннее 12
строк, даже если модель почти не предложила границ (например, посчитала
всю статью одной темой) — это подстраховка независимо от того, насколько
точно модель следует инструкции. Если OpenAI не настроен, отключён или
запрос не удался — используется локальная эвристика: соседние строки
склеиваются в один фрагмент, если их эмбеддинги семантически близки —
знаки препинания сами по себе ничего не решают, слишком много текста (адреса,
подписи, неформальные заметки) вообще без них обходится. Порог для
склеивания ниже, если строка перед ними не оканчивается точкой/!/?/: —
это слабая подсказка «незаконченной мысли» (например, «биллинг адрес»
перед строками «улица такая-то» / «город такой-то» / «индекс такой-то»),
но не более того: две подряд идущие строки без точки в конце, но на
разные темы, всё равно не попадут в один фрагмент — семантическая
близость проверяется всегда (`apps.assistant.chunking`). Абзац, вводящий список
или таблицу («Случаи, при которых возможен овердрафт.» перед списком этих
случаев), из-за этого попадает в индекс вместе со своим списком/таблицей
как одна цитата, а не по отдельности. После этого ответы на вопросы (при
снятой галочке «Спросить у ChatGPT») находят несколько таких фрагментов
**в пределах той статьи, на странице которой задан вопрос** — не по всей
базе знаний: ответ на вопрос под статьёй «Отпуска» может прийти только из
текста «Отпусков», даже если в другой статье формально есть более точное
совпадение. Из фрагментов текущей статьи финальный выбор делает
кросс-энкодер (`LOCAL_AI_CROSS_ENCODER_MODEL`) — маленькая модель, которая
смотрит на вопрос и кандидата вместе, а не сравнивает отдельно посчитанные
эмбеддинги, и поэтому точнее судит «отвечает ли это на вопрос», чем
косинусное сходство или пересечение по словам. Если кросс-энкодер не
уверен в лучшем варианте (низкий скор), под основным ответом показываются
1-2 следующих по релевантности кандидата — «Возможно, также относится».
Если кросс-энкодер недоступен (например, не удалось скачать веса),
используется пересечение по ключевым словам с учётом словоформ — и для
русского (через pymorphy3-лемматизацию: «рекламу»/«рекламы» — одно
слово), и для английского (через Porter-стемминг: «billing»/«billed» —
тоже одно слово). Возвращается точная цитата, не пересказ. Генеративная
модель здесь не используется: маленькие локальные модели либо копировали
фрагмент целиком, либо иногда отвечали не по теме — точный отрывок
надёжнее того и другого.

Кросс-энкодер сравнивает вопрос и кандидата по смыслу, но плохо различает
числа/коды («493711» и «493712» для него — просто похожие цифры). Если в
вопросе есть длинное число или буквенно-цифровой код (BIN, тариф, лимит) и
кандидат содержит это же значение буквально — он получает небольшую
надбавку к оценке при ранжировании: тайбрейкер между кандидатами с близкой
смысловой оценкой, а не замена самой оценки — явно менее подходящий по
смыслу кандидат с совпавшим числом всё равно не выигрывает у явно более
подходящего без него.

Слова возвращённой цитаты, совпавшие (с учётом лемматизации/стемминга) со
словами вопроса, подсвечиваются `<mark>` — чтобы сразу было видно, почему
выбран именно этот фрагмент, а не только что он выбран. То же самое
применяется и к «Возможно, также относится», и к обычному поиску по тексту
статьи, когда локальный ИИ ещё не обучен. Текст экранируется до вставки
подсветки (`apps.assistant.local_search.highlight_matches`, тот же приём,
что и в подсветке основного поиска по сайту, `apps.search.fts.
snippet_html`) — безопасно вставлять как HTML, даже если в статье
буквально встречаются символы `<`, `>` или `&`.

Обучение — это пересчёт индекса, а не тренировка модели с нуля: сама
модель эмбеддингов предобученная и скачивается с Hugging Face **один
раз**, при первом обучении, и кэшируется на диске. Модель кросс-энкодера
скачивается отдельно — тоже один раз, но при первом вопросе после
обучения, а не при самом обучении (она нужна только для ответа, не для
построения индекса). Для этого серверу, на котором развёрнуто приложение,
нужен исходящий HTTPS-доступ к `huggingface.co`. Модели и их общий кэш
задаются в `.env`:

Обе модели после загрузки остаются в памяти процесса до его перезапуска —
повторные вопросы не грузят их снова. Но сама первая загрузка (чтение
весов с диска, инициализация torch) занимает заметное время, и по
умолчанию происходит лениво, при первом реальном обращении — то есть
первый вопрос после каждого перезапуска/деплоя ждёт не поиск, а загрузку
моделей. `python manage.py warm_up_local_ai` загружает обе модели сразу
(no-op, если локальный ИИ ещё не обучен) — команда уже встроена в
`entrypoint.sh` и выполняется при каждом старте контейнера, перед тем как
поднимется сервер; при развёртывании без Docker её стоит вызвать вручную
после деплоя, рядом с `rebuild_search_index`/`rebuild_similarity_cache`.

После первого обучения индекс дальше поддерживается автоматически:
сохранение, переименование, архивирование/восстановление статьи или
откат к старой версии пересчитывают эмбеддинги только этой статьи в
фоновом потоке (`apps.assistant.signals` → `apps.assistant.training.
sync_article_embeddings`), без блокировки запроса и без нажатия
«Переобучить» — эта кнопка остаётся нужна только для первого запуска и
для полной пересборки (например, после смены `LOCAL_AI_EMBEDDING_MODEL`,
когда старые векторы уже не в одном пространстве с новыми). Пока
администратор не запустил обучение ни разу, сохранение статей не трогает
ML-модель вообще — не тянет веса и не грузит их в память впустую для тех,
кто этой функцией не пользуется.

```
LOCAL_AI_EMBEDDING_MODEL=intfloat/multilingual-e5-small
LOCAL_AI_CROSS_ENCODER_MODEL=cross-encoder/mmarco-mMiniLMv2-L12-H384-v1
LOCAL_AI_MODEL_CACHE_DIR=
```

По умолчанию — небольшая модель (~470 МБ), рассчитанная на работу на CPU
без GPU. Если веса скачать не удалось (нет сети, модель недоступна) — на
странице «Локальный ИИ» появится текст ошибки, а обучение не отметится
как выполненное; ответы на вопросы при этом продолжают работать через
обычный поиск по тексту статьи.
